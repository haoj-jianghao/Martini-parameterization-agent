# Build Martini models with an agent

## Rules (read first)

These rules come before everything below. A model built against them is not a result of this method, whatever its checks report.

1. **One molecule per agent session.** Each model is evidence that an agent applying this method to a molecule it has not seen produces a defensible model. A decision made once and applied to several molecules is not that evidence, and any error in it repeats across the batch. When several molecules are requested, do not build them in your session: start `scripts/batch.py run` (Batch mode), which gives each molecule its own session bound to its folder.
2. **Record decisions only with `scripts/design.py`, one decision per command.** The tool derives the index queries from the molecule, shows each reference bead by bead, records what you opened, and checks what you claim against it. A `design.json` written by hand or by your own code cannot show that the decisions were made for this molecule from these references. `build` flags such a record and the report states it.
3. **Every citation must support its claim.** Rung 1 means the source bead holds the same atoms; `design.py` verifies this and copies the type. When no precedent holds the fragment, say so and use rung 2 or 3. An honestly marked provisional type is a valid result; a type attributed to a source that does not contain it is not.
4. **Report what happened.** Blocked, partial and provisional outcomes are acceptable results. An outcome made to look complete is not. Finishing quickly is not a goal; when a rule makes the work slower, the slower path is the method.

## Modes and contract

Use the LLM for mapping, bead types and charges. Use deterministic code for bonded terms, graph inspection, geometry, file writing and numerical checks. The agent does not choose bonded terms or their values. Deliver a candidate model or an explicit partial result that says what is unresolved. Never claim physical validation from generated files or short dynamics alone.

- **Prepare:** follow `references/environment.md` (section 0 when starting from the release bundle; check it with `scripts/reference_manifest.py verify`); use `assets/environment.example.json`. Acquire fixed references, build the index with `scripts/build_index.py` and lock them before generation.
- **Generate:** accept SMILES and environment JSON path. After configuration, SMILES is the only required molecular input. Follow the stages below.
- **Compare:** only after freezing an independent result, follow `references/comparison.md`. It matches beads through their atoms, then reports bead counts, bead-vs-bead size/type/polarity differences, bonded-term differences, and radius of gyration and SASA without MD. A reference model (for example Auto-Martini's) is a comparator, not ground truth, and is never simulated.

Generate mode runs these commands in order, each with `python_command`, from one molecule folder `<moldir>`:

| Command | Does | Needs |
| --- | --- | --- |
| `scripts/cgbuild.py input <moldir> --smiles S --id ID --name NAME --aa-topology FILE` | Freezes the indexed structure and conformers; checks and copies the user's OPLS-AA topology | SMILES, OPLS-AA topology |
| `scripts/design.py init <moldir>` | Derives index queries from the molecule, runs the search, prints the atom table and ranked hits | `input` |
| `scripts/design.py open / match / query / annotate` | Shows a reference bead by bead and records it as opened; lists indexed beads holding a proposed fragment; adds a query; records why a reference was used or not | `init` |
| `scripts/design.py candidate / choose / bead / vsite / note` | Records your mapping candidates, choice, each bead with its typing rung, virtual sites and notes in `decisions/design.json` (stages 2 and 3) | `init` |
| `scripts/design.py check <moldir>` | Reports what the design still lacks and refreshes `decisions/analogue_search.json` | beads |
| `scripts/cgbuild.py bonded <moldir>` | Derives all bonded terms (stage 4) | The supplied OPLS-AA topology |
| `scripts/cgbuild.py build <moldir>` | Writes ITP, GRO, drawing, records and static checks | `bonded.json` |
| `scripts/cgbuild.py test <moldir>` | Solvates, adds counterions, runs EM, equilibration and the smoke test | GROMACS |
| `scripts/cgbuild.py finalize <moldir>` | Writes validation, manifest and report; freezes `baseline/` | |
| `scripts/multi_seed_check.py OUT <moldir>` | Repeats EM and equilibration with other seeds (stage 5) | GROMACS |
| `scripts/sasa_check.py OUT <moldir>` | Report-only SASA of the mapped model against its D5 atomistic ensemble (stage 6) | GROMACS |

`scripts/design.py --help` lists every command and argument. The environment file is `$MARTINI_ENV`, or `environment.json` next to the skill folder. `$MARTINI_GMX_THREADS` sets the `mdrun` threads (default 4). Leave `OMP_NUM_THREADS` unset: GROMACS rejects a mismatch with `-ntomp` and every test fails. `scripts/cgbuild.py summary <batchdir>` writes a batch report.

Read `references/data-contract.md` before writing run files and `references/validation.md` before simulation. Resolve relative paths against the environment JSON directory. Do not assume the skill directory is the molecular workspace.

## Experiment boundary

Allow RDKit, Python/NumPy/SciPy, generic graph/geometry libraries, drawing, reference search, PDF rendering, GROMACS, and for stage 4 an OPLS-AA topology of the molecule supplied by the user (made by any OPLS engine, with any charge method), or, if none is supplied and `opls_ff_gen_command` is set, that engine. Do not invoke, import, copy decision algorithms from, or use generated output from Auto-Martini, SMartini, SwarmCG, CGCompiler, Martini Mapper, martinize or other automatic CG parameter generators during generation. Generic parsers and deterministic bookkeeping are allowed.

Allow documented reference fragments and analogous published models. For strict holdout tests use a precurated reference subset; do not search a full topology file containing the target. If the target topology has been seen, mark `reference_exposed`; do not call the run blind independent generation. Do not silently clear that flag. General guidelines and bead definitions remain allowed.

Cite every factual claim, chemical decision and numerical value to a pinned file under the reference root (path plus locator: section, page, table, moleculetype or line), or to a reproducible calculation in the run. Label anything not cited that way, including recalled literature, citations, model names, experimental values and rules of thumb, exactly "agent background knowledge, unverified" wherever it appears (decisions, parameter records, comments, report). Unverified knowledge may suggest what to look for, but it cannot by itself justify a bead type, a mapping or a numerical parameter: such a term is `unresolved`. If a pinned file later confirms or contradicts the statement, cite it; correct visibly and do not delete the original statement. Record each with `design.py note --unverified`; the report lists them all.

Parameterization is MD-free: stage 4 evaluates conformer energies, minima and Hessians with an OPLS force field and runs no dynamics. Do not run AA MD, Bartender or iterative bonded fitting by default. If explicitly enabled, mark `assisted_refinement` and preserve the baseline. The only dynamics in the workflow are the CG execution checks of the finished model. Never alter the nonbonded interaction matrix or introduce new bead types in this workflow.

## 1. Preflight and identity

1. Read environment configuration. Run all Python (helpers, RDKit, run scripts) with the interpreter in `python_command`; confirm it imports RDKit before generation and record its path and version. Confirm that it also imports NumPy and SciPy. Ask the user for an OPLS-AA GROMACS topology (`.top`, or `.itp` with `[ atomtypes ]`) of each molecule in the protonation state of its SMILES, and pass it to `cgbuild.py input --aa-topology` (with `--aa-engine` and `--aa-charge-model` if the user states them). If none is given, use `opls_ff_gen_command` if it is set and runs; otherwise stage 4 is `blocked`. Run `scripts/reference_lock.py verify REFERENCE_ROOT LOCK_FILE`. Explain missing/changed references before numerical assignment; do not silently relock. The script checks integrity, not scientific completeness.
2. Confirm selected core ITP, solvent/ion dependencies, relevant paper/SI, Bible, examples, tutorial and matching GROMACS documentation exist. Inspect actual content. Use only approved paths. Record source hashes, software versions, skill hash, seeds, agent/model identifier if available and tool actions.
3. Parse/sanitize SMILES using RDKit. Preserve encoded charge, protonation, tautomer and stereochemistry; save original and canonical isomeric SMILES. Document disconnected components and unspecified stereochemistry. Ask only where ambiguity changes the intended species; never silently neutralize or remove salts.
4. Freeze an explicit-H atom-indexed structure and atom table. Use stable one-based IDs, preserving conversion to RDKit zero-based indices. Generate at most 10 conformers with seed 20261031 by default. Record geometry optimization method/convergence. Preserve SDF atom ordering and chirality. A minimized conformer is not a thermodynamic ensemble. Report failed embedding rather than inventing coordinates.

## 2. Choose mapping

1. Search the reference index (`reference_index`, `models.jsonl`) before choosing a mapping. `design.py init` derives the queries from the molecule (its ring systems, ring-substituent junctions, functional groups with their neighbouring atoms and aliphatic chains), runs them against the index and the Bible, and ranks the hits by similarity to the target. Add a query with `design.py query` when a motif is missing. Open every relevant hit with `design.py open`, which shows its beads, types and member atoms and records the files; read its figure when the mapping is unclear. Give every opened reference a reason with `design.py annotate` (used references are annotated by `design.py bead`). The search, hits and reasons are recorded in `decisions/analogue_search.json`. A target found in the index or the Bible, as the same constitution or as another tautomer of it (RDKit canonical tautomer, checked by `cgbuild.py search`), sets `reference_exposed`.
2. Read relevant Bible entries, original SI and the analogous model mappings found above. Cite exact file/page/table/molecule section for transferred decisions. Render figures when text cannot convey chemical mapping.
3. **Partition first, type second.** Cut the molecule into fragments before choosing any bead type (Souza 2021 SI section C1, p. 36):
   - A bead is a fragment of its heavy atoms. 4-1, 3-1 and 2-1 fragments default to R, S and T beads. Aromatic ring fragments are T, or S with a substituent; aliphatic rings use S; a fully branched fragment takes a smaller bead (neopentane, 5 atoms, is R). Keep the whole molecule within ±1 heavy atom per 10 of what its beads represent.
   - Do not divide a chemical group (amide, carboxylate, ester) between beads, and do not isolate it either: a functional group goes into a 2–4-atom fragment with its neighbouring carbons (methoxy C–O, hydroxyethyl C–C–OH, phenol C–OH with its ring CH). A lone heteroatom or a lone carbon is not a bead; the only published exceptions are listed in `cgbuild.bead_size_issue` (for example the S of thiophene).
   - Never choose a cut to make a bead match a precedent's type. Precedents guide where to cut only when the same atoms form the same bead there; the type is assigned afterwards (stage 3).
   - `cgbuild.py build` flags every bead whose size does not fit its heavy atoms (`bead_size_matches_heavy_atoms`). Change the mapping, or give the bead a `size_exception` (`design.py bead --size-exception`) that cites a published model with the same atoms in a bead of that size.
4. Propose at most three plausible mappings without exhaustive global enumeration. Consider functional groups, symmetry, charge localization, branching, ring shape, resolution, overall volume and motif junctions.
5. Work in full-molecule context. Local decomposition is allowed; inspect each junction and conjugated group. Do not blindly concatenate fragment topologies.
   - **Choosing among precedents.** When several documented models cover the same fragment, start from the closest context, in this order: (a) the same ring system with the same fusion, as a published model (for example the force-field nucleobases for purines and pyrimidines, CAFF for xanthines); (b) the same fused ring pair with other substituents (BZIM, INDO, QUIN); (c) the isolated ring (IMID, PYMI, PYRI). Take its bead split and hinge layout first. Moving down the order, or departing from that precedent's split, is allowed when chemistry or geometry justifies it (a substituent, tautomer or protonation change, or a virtual site that misses the 0.05 nm limit); state the reason in the bead rationale and in the rejection reason of the closer precedent. Different defensible mappings are acceptable, as between chemists; an unexplained departure from a closer precedent is not.
   - **Junctions between a rigid group and a flexible part** (for example the glycosidic N9–C1′ of a nucleoside): keep each atom in a bead of its own part. Do not put an atom of a flexible ring or chain into a rigid-group bead. Otherwise several flexible beads connect to the rigid group, stage 4 bridges each to it, and the flexible part is over-restrained.
6. Record each candidate with `design.py candidate` (atoms as `1,2,3|4,5:0.5,...`, with its own summary, pros and cons), then `design.py choose` with the selection rationale. The candidate output lists, for each bead, how many indexed beads hold the same fragment and their types. Declare all atom contributions and intentional shared-atom allocation weights. `build` draws the mapping over the indexed molecule.
7. Every bead must contain at least one atom; `cgbuild` cannot hold a bead with no atoms (for example the central TC4 of the Bible glucose). When a documented model has one, transfer the other beads and record the omission as a deviation.
8. Check connected groups, atom coverage and intentional overlap. Allocation weights sum to one across beads for each AA atom; normalize within each bead to compute its center of geometry. Include hydrogens per the source convention. Mapping weights do not define bead masses.

## 3. Assign types and charge

Parse allowed types from the pinned core ITP. Use documented chemical/size/polarity/label precedents, including substituent effects. Verify every chosen name exists. Do not borrow a later extension silently. Assign net charge from intended chemical state and compatible documented models, not arbitrary sums of atomistic partial charges. Record a source-backed assignment for every bead.

Type each bead by this ladder with `design.py bead`, which records the rung used and what each earlier rung found. `design.py match --atoms ...` lists every indexed bead that holds the same fragment, with its type:
1. The same fragment typed in an indexed model or Bible entry → `transferred`. Same fragment means the same heavy atoms in the same bonding context, checked in the source's mapping file (`.ndx`/`.map`) or Bible entry: the source bead must hold what your bead holds, no fewer and no more atoms. Copy the type of that bead, not of a neighbouring one. A type taken from a source bead with other atoms (for example the SN3ar of a C–O–C bead given to a lone ether oxygen) is not rung 1; go to rung 2. Record it as `design.py bead --rung 1 --from REF_ID:BEAD` on an opened reference: the tool compares the fragment signatures and copies the type. The signature compares the bead's own atoms and the bonds leaving it, not the atoms beyond them (Bible fragments do not record those). When the neighbours differ in a way the SI proximity rules cover (conjugation, induction, local dipole), say so in the rationale, or use rung 2. When precedents disagree on the type, choose by the closest context (stage 2.5) and say why in the rationale.
2. The nearest documented chemical group (Souza SI Table 24/25), refined with the SI proximity rules (section C2: inductive/conjugation, local dipole, internal H-bonds, resolution) → `adapted`, naming the group and the rule applied (`--group`, `--rule`, `--source PATH:LOCATOR`). If rung 1 was available, `--rung1-rejection` says why it was not used.
3. No matching group: select the type from the partitioning data of the isolated fragment, as the SI prescribes (Souza SI section C introduction, step 2, p. 35; Supplementary Tables 17–19) → `adapted`, citing the table and values (`--table`, `--values`, `--rung2-finding`).
4. Only if all three fail: `unresolved`. Record what each rung found with `design.py note --limitation`; the model is `blocked`.

A type from rung 2 or 3 for chemistry with no direct precedent (for example a carbonate or a conjugated lactone) is a provisional type: it does not block execution, but it must be flagged `provisional_type` and listed in the report.

## 4. Derive bonded model

Run `scripts/cgbuild.py bonded <moldir>`. It takes the SMILES and the frozen mapping, and writes `decisions/bonded.json`. Do not write bonded terms, exclusions or `nrexcl` in `design.json`, and do not edit `bonded.json`. The method is in `references/bonded.md`.

Your remaining decisions are in the mapping:
1. **Fused rings.** Follow the SI hinge (Souza SI section C4, p. 45-46), as the published polycyclics do (NAPH, QUIN, ANTH, CAFF, TECE): four real beads forming the hinge, and the other ring beads as virtual sites. Declare each with `design.py vsite`, with `construction` set to `virtual_sitesn_cog` (centre of the constructing beads) or `virtual_sites3` (an in-plane position). You choose the site and its constructing beads; stage 4 computes the coefficients. A rigid group above four real beads is `blocked`, so change the mapping. If a site is over 0.05 nm from its mapped position, change the construction or move side-chain atoms out of that bead. Avoid a near-straight rigid triangle (`near_linear_rigid_triangle`).
2. **Masses** are computed, not chosen. Each bead gets its standard size mass (R 72, S 54, T 36), each virtual site 0, and each site's standard mass is split equally over the real beads of its rigid group, keeping the total (CAFF 4 × 63, BZIM 4 × 45). A site outside any rigid group passes its mass to its constructing beads. Stage 4 and `build` use the same rule (`d5bonded/terms.py`, `bead_masses`) and record it in `bonded.json` `masses`. Do not write `mass_amu` in `design.json`; `build` ignores it and lists any difference under the mass check.

Read `bonded.json` before building: its `flags`, its `dropped` list, and any term whose `limitations` says a value was capped or floored. If stage 4 fails (the topology, the OPLS engine or the energy model), the model is `blocked`; report it and do not substitute hand-chosen values.

## Batch mode

Several molecules are built by `scripts/batch.py run --molecules FILE.tsv --batch NAME --agent claude|codex --model MODEL`, not in one agent session. The TSV lists `id`, `name`, `smiles` and `aa_topology` (the user's OPLS-AA topology for each molecule), plus optional `aa_engine` and `aa_charge_model`. The launcher creates one folder per molecule and starts one headless agent session for each, using the prompt in `assets/agent_prompt.md`, with `MARTINI_MOLDIR` set to that folder. In that session `design.py` and `cgbuild.py` refuse any other folder, and `batch.py` refuses to start. Each molecule therefore gets its own index search, mapping candidates and typing ladder, and no decision is shared across molecules. Stage 4 is shared deterministic code by design. Agent command lines can be changed in `environment.json` (`agent_commands`). The launcher writes `batch.json` (the launch record) and the logs, then runs `cgbuild.py summary`. The summary shows, for each molecule, whether it was built in its own session and whether its design was recorded with `design.py`. If you are asked for several molecules, prepare the TSV, run the launcher (or give the user the command), and report from the summary.

Before starting any session, the launcher checks without an API call that the sessions can write the agent CLI's state folder and reach its service. An agent sandbox often blocks both, so a launcher started from inside one cannot start child sessions. If that check fails, or a session ends without doing any molecule work, the launcher starts no further sessions, exits with code 3 and writes `FALLBACK.md` in the batch folder. Each molecule folder already holds its `agent_prompt.txt` and `agent_env.sh`. Tell the user the reason and that the command can be rerun outside the sandbox. You may then finish the batch with your own sub-agents as `FALLBACK.md` describes: one fresh sub-agent per remaining molecule, given that molecule's prompt unchanged and nothing from other molecules. Then run `cgbuild.py summary` on the batch folder and report from it. The summary takes the launch path of each molecule from its design log. Do not report the sub-agents' model as the requested model unless your dispatcher states it.

## 5. Emit and check

`finalize` copies the deterministic generation code into the run's `scripts/`. Emit ITP/GRO, mapping and parameter records, drawing, minimal system TOP, adapted EM/equilibration/test MDPs and dependency manifest. Ensure include ordering, one defaults definition, no duplicate molecule definitions and identical topology/coordinate ordering. Bundle compatible dependencies if permitted or record exact paths/hashes.

Run `scripts/cgbuild.py build`, `test` and `finalize`. Follow `references/validation.md`. Default to one molecule in compatible Martini water; `test` neutralizes charged molecules with NA or CL. Report missing solvent or GROMACS; never imply execution. Use at most three repair cycles with retained versions and reasons. For stiff or fused molecules, also run `scripts/multi_seed_check.py`, because one passing run can be chance, and report how many seeds passed. Do not achieve stability through indiscriminate stiffening, freezing flexible groups, suppressing warnings or deleting interactions. If a model fails, report the failing term and bonded rule. A repair changes the mapping or virtual sites, or is recorded as a manual intervention.

Freeze `baseline/` with hashes before opening benchmarks. Report chemistry checks, numerical execution and physical evaluation separately. Isolate failures in batch mode. Never promote generated provisional models to the reference library automatically.

## 6. Deliver

Provide model files, test inputs, mapping, provenance, dependencies and report. State bead count, charge, analogues, provisional types, the AA topology used (supplied or engine; its stated engine and charge method), bonded flags, seeds tested, tested timestep/duration, actual checks, deviations and reference exposure. Compute every status, count and list in the report from the run's records (mapping, parameters, analogue search, validation, manifest); never write them from a template. Reports carry no claim about a molecule that its records do not support. List all statements labelled "agent background knowledge, unverified". Report statuses `blocked`, `constructed_unexecuted`, `preprocessed` or `execution_checked`; store physical observables separately. Report the SASA band (pass within 5%, review to 10%, flag above 10%) if `sasa_check.py` was run. It changes no model or status, and do not change bond lengths to meet it without a recorded decision. If dependencies prevent completion, list concrete pending actions and deliver available work without claiming success. Do not invent calibrated confidence scores.
